# Fitur "Saved SOW" (Simpan SOW yang Diedit & Load Ulang) — Implementation Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** User bisa menyimpan SOW yang sedang diedit (dengan nama), lalu kapan pun — termasuk setelah memilih component LAIN di create — me-load kembali SOW tersebut beserta SEMUA editannya (jam VA/NNVA, op custom, info). Template bisa di-rename.

**Architecture:** Fitur BARU terpisah `sow_saved` (tabel + endpoint + panel FE) berbasis snapshot JSONB — pola sama seperti `sow_draft`, tapi durable, bernama, listable, dan shared. Sistem template standard yang ADA (`sow_templates`, 2.972 row di prod) TIDAK disentuh — tetap jalan sebagai "Operation Packages". Tombol "Save as Template" yang broken diwiring ke fitur baru (atau direlabel).

**Tech Stack:** Express + Postgres JSONB (backend); React 19 + Vite (FE); RBAC manifest; migration manual ke CKP + BPN.

## DESAIN

### Tabel `sow_saved` (baru)

```sql
CREATE TABLE IF NOT EXISTS sow_saved (
  id           BIGSERIAL PRIMARY KEY,
  name         TEXT NOT NULL,               -- nama snapshot (bisa di-rename)
  component_id INTEGER,                     -- opsional: component asal (info saja, load TETAP bebas)
  payload      JSONB NOT NULL,              -- snapshot state create: selectedPart/cardInfo/editOps(+jam+remark)
  created_by   TEXT,
  created_at   TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at   TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
CREATE INDEX IF NOT EXISTS idx_sow_saved_name ON sow_saved (lower(name));
```

- Payload = subset state draft: `{ selectedPart, cardInfo, editOps }` — editOps membawa operation_no/text/machineid/std_hours/va_hours/nnva_hours/remark/source_op_id. **Tanpa operationCardImages** (gambar operation card = artefak per order, bukan isi snapshot; bisa ditambah belakangan).
- Shared (semua user sow_management bisa lihat & pakai) — keputusan 1a, kerja tim planner. `created_by` cuma info.

### Endpoint (semua `/sow`, RBAC `sow_management` W; GET list boleh R/W — konvensi manifest write-only, GET tanpa entri)

| Method | Path | Fungsi | Keterangan |
|---|---|---|---|
| POST | `/sow/saved` | `createSavedSow` | Simpan snapshot + nama; 201 `{id}` |
| GET | `/sow/saved` | `listSavedSows` | List ringkas: id, name, ops count, total jam, updated_at, created_by (search `?q=`) |
| GET | `/sow/saved/:id` | `getSavedSow` | Ambil payload penuh untuk load |
| PUT | `/sow/saved/:id` | `updateSavedSow` | Rename (name) DAN/ATAU update payload; 200 |
| DELETE | `/sow/saved/:id` | `deleteSavedSow` | Hapus; 204 |

- Route diletakkan DI ATAS route generic `/:order` (legacy) di routes/sow.js.
- `ensureSowSavedTable()` runtime (pola `ensureSowDraftTable`) + migration file.

## Risks & tradeoffs

1. **Tombol "Save as Template" broken dihapus/diganti** — tidak ada kehilangan (fitur itu TIDAK PERNAH bekerja; 2.972 template di DB dibuat lewat jalur lain). Template standard tetap utuh.
2. **Snapshot tanpa gambar operation card** — kalau ternyata dibutuhkan, payload diperluas (perhatikan limit 10mb).
3. **Saved SOW shared antar user** — tanpa ownership; kalau mau per-user, tambah kolom user_key (keputusan 1b).
4. **Snapshot bisa basi** (master berubah) — sifatnya copy-on-save, memang disengaja (user mau "editan yang disimpan", bukan referensi live).

## Keputusan yang diminta user (konfirmasi, pola 1a/2a/3a/4a)

1. **Scope visibility**: 1a = shared semua user sow_management (rekomendasi, kerja tim) vs 1b = per-user
2. **Tombol "Save as Template" broken**: 2a = ganti jadi "Save SOW" (snapshot, rekomendasi) vs 2b = wiring jadi bikin standard-op template beneran (jam edit tidak tersimpan, op custom tidak bisa)
3. **Model**: 3a = tabel baru `sow_saved` payload JSONB (rekomendasi) vs 3b = extend `sow_templates` dengan kolom payload (campur semantik, risiko 2.972 data)
4. **Posisi panel load**: 4a = panel list di awal create + modal Save (rekomendasi) vs 4b = dropdown picker ringkas
