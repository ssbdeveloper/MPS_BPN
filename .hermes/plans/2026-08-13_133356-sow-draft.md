# Fitur Draft SOW (Create SOW & Edit SOW History) — Implementation Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Pengguna tidak kehilangan pekerjaan saat create SOW atau edit SOW history ketika app crash / browser tertutup / ada trouble — form state ter-autosave ke tabel DB dan bisa dipulihkan ("Lanjutkan draft").

**Architecture:** Tabel baru `sow_draft` (Postgres, JSONB payload) + 3 endpoint draft di sowController (semua scoped per-user via header `x-user`). FE memakai satu shared hook `useSowDraft` yang (a) autosave debounce ~1.5s + `pagehide`, (b) restore banner saat mount, (c) hapus draft setelah save final sukses. Hook dipakai di SowCreatePage (create) dan SowRevisionEditPage (edit history), opsional SowHistoryPage (inline edit modal).

**Tech Stack:** Express (CommonJS) + node-pg + Postgres JSONB; React 19 + Vite (FE); RBAC manifest; migration manual ke CKP.

## Desain

### Tabel `sow_draft`

```sql
CREATE TABLE IF NOT EXISTS sow_draft (
  id         BIGSERIAL PRIMARY KEY,
  user_key   TEXT NOT NULL,              -- req.user.username / 'web'
  context    TEXT NOT NULL,              -- 'create' | 'revision' | 'history-edit'
  ref_key    TEXT NOT NULL DEFAULT '',   -- order_no (revision/history-edit); '' utk create
  payload    JSONB NOT NULL,             -- snapshot state FE (disimpan apa adanya)
  updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  UNIQUE (user_key, context, ref_key)
);
CREATE INDEX IF NOT EXISTS idx_sow_draft_user_updated
  ON sow_draft (user_key, updated_at DESC);
```

- **1 draft per (user, context, ref_key)** — autosave = overwrite (UPSERT). Restore = baca key itu. Tidak ada draft list UI (YAGNI).
- `context`/`ref_key`: `create` + `''` untuk SowCreatePage; `revision` + `orderNo` untuk SowRevisionEditPage; `history-edit` + `orderNo` untuk SowHistoryPage (opsional).
- Payload JSONB = serialisasi state FE apa adanya (termasuk `_key`/`_srcId`/`_isNew` ephemeral fields — FE restore langsung `setState`, tidak perlu re-normalize).

### Endpoint (semua di bawah `/sow`, RBAC `sow_management`)

| Method | Path | Fungsi | Keterangan |
|---|---|---|---|
| PUT | `/sow/drafts/:context/:refKey` | `saveSowDraft` | Upsert payload; set `updated_at=NOW()`; 200 `{saved_at}` |
| GET | `/sow/drafts/:context/:refKey` | `getSowDraft` | 200 `{draft}` / 404 bila tidak ada; scoped user |
| DELETE | `/sow/drafts/:context/:refKey` | `deleteSowDraft` | Hapus (setelah save final sukses / tombol Buang); 204 |

- `refKey` URL-encoded (order_no bisa berisi karakter aneh). `user_key` TIDAK pernah dari client — dari `req.user?.username || 'web'`.
- Route diletakkan DI ATAS route legacy `/:order` di `routes/sow.js`.
- `ensureSowDraftTable()` mengikuti pola `ensureSowRevisionHistoryTable` (runtime CREATE TABLE IF NOT EXISTS + migration file tetap ditulis & di-apply manual untuk konsistensi).

### Hook FE `useSowDraft` (baru: `apps/web/src/features/sow/useSowDraft.js`)

API: `useSowDraft({ context, refKey, state, enabled, onRestore })` → `{ draftAvailable, restoreDraft, discardDraft, lastSavedAt }`

Behavior:
1. **Mount**: GET draft → kalau ada, `draftAvailable=true` + render banner (toast/banner inline) "Draft tersimpan HH:MM — Lanjutkan / Buang".
2. **Lanjutkan**: `onRestore(payload)` → setState FE dari payload → `draftAvailable=false`.
3. **Buang**: DELETE draft → `draftAvailable=false`.
4. **Autosave**: debounce 1.5s setelah `state` berubah; HANYA jika `enabled` (initial load selesai — cegah state kosong menimpa draft lama) dan belum pernah restore/save final.
5. **`pagehide`**: kirim last-chance save (fetch `keepalive: true` atau `navigator.sendBeacon` dengan JSON payload dari ref terbaru).
6. **413 fallback**: kalau PUT draft gagal karena payload > 10mb (images base64), retry sekali tanpa `operationCardImages` — teks tetap aman.

## Risks & open questions

1. **Payload > 10mb** (operation card images base64 banyak) → fallback simpan tanpa images (teks tetap). Batas ini dokumentasikan.
2. **Draft usang**: draft tidak punya TTL — user yang buka bulan depan masih dapat draft lama. Opsi: tampilkan timestamp di banner; tidak auto-delete (keep simple). Kalau mau, tambah TTL 7 hari di query GET (bisa jadi keputusan lanjutan).
3. **Dua tab edit order sama** → draft saling menimpa (last-write-wins). Diterima (edge case).
4. **StrictMode dev**: hook harus idempotent (interval cleanup benar) — pitfall skill `mountedRef` diingat.
5. **RBAC GET draft**: pilih W (konsisten dengan page yang guarded `sow_management`) — tidak ada endpoint draft yang boleh diakses user non-sow.
6. **Scope SowHistoryPage inline edit** — keputusan user (Task 6).

## Keputusan yang diminta user (konfirmasi cepat, pola 1a 2a 3a)

1. **Scope draft**: (1a) Create SOW + Revision editor saja, atau (1b) sekalian inline edit modal di SowHistoryPage? — rekomendasi **1b** (murah, hook sama, coverage penuh).
