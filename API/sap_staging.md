# SAP Timesheet Staging Plan

## Tujuan

Semua payload timesheet ke SAP masuk ke staging dulu, baru diposting dari staging.

Source yang masuk staging:

- `timesheet_transaction`
- `mch_transaction` setelah dibundle per 1 jam

Alasan staging:

- `ZTIMESHEETID` autogenerated dan konsisten untuk semua source.
- Payload yang sudah dibuat tidak berubah saat retry.
- Anti-double dikunci lewat `source_key`.
- Posting SAP bisa dipisah dari proses validasi/bundling.

## Keputusan ZTIMESHEETID

Strategi lama `ZTIMESHEETID = WERKS + sequence_no` diganti.

Strategi baru:

```text
ZTIMESHEETID = id staging
```

`id` dibuat oleh PostgreSQL dengan identity/autoincrement.

```sql
id bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY
ztimesheetid text GENERATED ALWAYS AS (id::text) STORED
```

Konsekuensi:

- Tidak perlu table sequence manual.
- Tidak perlu lock sequence per plant.
- Nomor increment dikontrol database.
- Gap nomor boleh terjadi jika insert gagal/rollback/concurrency, yang penting tidak double.
- `ZTIMESHEETID` tidak lagi bergantung ke `tsnumber`, `proddataid`, atau plant.

## Anti Double Strategy

Anti-double wajib pakai `source_key`.

Rule:

- Setiap row staging punya `source_system`.
- Setiap source punya `source_key`.
- `UNIQUE (source_system, source_key)` mencegah data yang sama masuk dua kali.
- Script boleh dijalankan ulang; duplicate akan di-skip dengan `ON CONFLICT DO NOTHING`.

Source key:

```text
TIMESHEET:
  source_system = 'TIMESHEET'
  source_key = tsnumber

MCH_HOURS:
  source_system = 'MCH_HOURS'
  source_key = md5(werks + bucket_start + payload grouping fields)
```

Untuk machine hours, `source_key` tidak boleh memasukkan `total_seconds`, karena jika raw data berubah untuk bucket yang sama, kita perlu mendeteksi konflik sebagai data yang sama secara business key. Rebuild untuk bucket yang sudah staging harus lewat mekanisme khusus, bukan silent duplicate.

## Staging Table

Satu table untuk semua payload SAP timesheet.

```sql
CREATE TABLE IF NOT EXISTS sap_timesheet_staging (
  id bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  ztimesheetid text GENERATED ALWAYS AS (id::text) STORED,

  source_system text NOT NULL,
  source_key text NOT NULL,
  source_ref_id text,

  werks text NOT NULL DEFAULT '',
  pernr text NOT NULL DEFAULT '',
  rueck text NOT NULL DEFAULT '',
  aufnr text NOT NULL DEFAULT '',
  vornr text NOT NULL DEFAULT '',
  flgat text NOT NULL DEFAULT '',
  plnfl text NOT NULL DEFAULT '',
  vornr_b text NOT NULL DEFAULT '',
  vornr_r text NOT NULL DEFAULT '',
  zconf_type text NOT NULL DEFAULT '',
  arbpl text NOT NULL DEFAULT '',
  lstar text NOT NULL DEFAULT '',
  isdd text NOT NULL DEFAULT '',
  isdz text NOT NULL DEFAULT '',
  iedd text NOT NULL DEFAULT '',
  iedz text NOT NULL DEFAULT '',
  aueru text NOT NULL DEFAULT '',
  zbarcodeid text NOT NULL DEFAULT '',

  payload jsonb NOT NULL DEFAULT '{}'::jsonb,

  bucket_start timestamp without time zone,
  synthetic_start timestamp without time zone,
  synthetic_end timestamp without time zone,
  total_seconds bigint,

  source_row_count integer NOT NULL DEFAULT 1,
  source_min_start timestamp without time zone,
  source_max_end timestamp without time zone,

  status text NOT NULL DEFAULT 'PENDING',
  sap_response jsonb,
  sap_response_text text,
  sap_error text,
  posted_at timestamptz,
  created_at timestamptz NOT NULL DEFAULT now(),
  updated_at timestamptz NOT NULL DEFAULT now(),

  CONSTRAINT sap_timesheet_staging_source_uk UNIQUE (source_system, source_key),
  CONSTRAINT sap_timesheet_staging_status_ck CHECK (
    status IN ('PENDING', 'POSTING', 'POSTED', 'FAILED', 'SKIPPED')
  ),
  CONSTRAINT sap_timesheet_staging_source_system_ck CHECK (
    source_system IN ('TIMESHEET', 'MCH_HOURS')
  )
);

CREATE INDEX IF NOT EXISTS sap_timesheet_staging_status_idx
  ON sap_timesheet_staging (status, created_at);

CREATE INDEX IF NOT EXISTS sap_timesheet_staging_source_idx
  ON sap_timesheet_staging (source_system, source_ref_id);

CREATE INDEX IF NOT EXISTS sap_timesheet_staging_bucket_idx
  ON sap_timesheet_staging (source_system, bucket_start);
```

Catatan penting: karena `payload` butuh `ZTIMESHEETID`, payload final dibuat setelah row mendapat `id`. Kolom `payload` punya default `{}` supaya insert awal tetap valid. Pola insert:

1. Insert data payload columns tanpa `payload`.
2. `RETURNING id`.
3. Update `payload = jsonb_build_object(...)` memakai `ztimesheetid`.

### Timesheet Staging Query

```sql
WITH rows AS (
  SELECT
    t.tsnumber,
    t.serialnumber,
    t.order_no,
    t.operation_no,
    t.workcentercode,
    t.activitytype,
    t.operation_text,
    t.plant,
    t.longdate_checkin,
    t.longdate_checkout,
    TO_CHAR(t.longdate_checkin  AT TIME ZONE %(timezone)s, 'YYYYMMDD') AS isdd,
    TO_CHAR(t.longdate_checkin  AT TIME ZONE %(timezone)s, 'HH24MISS') AS isdz,
    TO_CHAR(t.longdate_checkout AT TIME ZONE %(timezone)s, 'YYYYMMDD') AS iedd,
    TO_CHAR(t.longdate_checkout AT TIME ZONE %(timezone)s, 'HH24MISS') AS iedz,
    po.confirmation_number,
    po.sequence_category,
    po.sequence_number,
    po.branch_operation_no,
    po.return_operation_no
  FROM timesheet_transaction t
  LEFT JOIN ph3_order po
    ON LTRIM(po.order_no, '0') = t.order_no
   AND LTRIM(po.operation_no, '0') = t.operation_no::text
  WHERE t.tsnumber = ANY(%(tsnumbers)s::int[])
    AND t.longdate_checkin IS NOT NULL
    AND t.longdate_checkout IS NOT NULL
    AND t.longdate_checkout > t.longdate_checkin
    AND COALESCE(t.state_flag, 0) <> 5
),
payload_columns AS (
  SELECT
    'TIMESHEET' AS source_system,
    tsnumber::text AS source_key,
    tsnumber::text AS source_ref_id,
    COALESCE(plant, '') AS werks,
    CASE
      WHEN COALESCE(employee_category, '') ILIKE '%Outsource%' THEN '11009413'
      ELSE LPAD(COALESCE(serialnumber, ''), 8, '0')
    END AS pernr,
    CASE WHEN COALESCE(activitytype, '') <> '' THEN '' ELSE COALESCE(confirmation_number, '') END AS rueck,
    CASE WHEN COALESCE(activitytype, '') <> '' THEN '' ELSE LPAD(COALESCE(order_no, ''), 12, '0') END AS aufnr,
    CASE WHEN COALESCE(activitytype, '') <> '' THEN '' ELSE LPAD(COALESCE(operation_no::text, ''), 4, '0') END AS vornr,
    CASE WHEN COALESCE(activitytype, '') <> '' THEN '' ELSE COALESCE(sequence_category, '') END AS flgat,
    CASE WHEN COALESCE(activitytype, '') <> '' THEN '' ELSE COALESCE(sequence_number, '') END AS plnfl,
    CASE WHEN COALESCE(activitytype, '') <> '' THEN '' ELSE COALESCE(branch_operation_no, '') END AS vornr_b,
    CASE WHEN COALESCE(activitytype, '') <> '' THEN '' ELSE COALESCE(return_operation_no, '') END AS vornr_r,
    CASE
      WHEN COALESCE(activitytype, '') <> '' THEN ''
      WHEN COALESCE(workcentercode, '') LIKE '%OT' THEN 'OV'
      WHEN order_no LIKE '32%' THEN 'RW'
      ELSE 'RG'
    END AS zconf_type,
    COALESCE(workcentercode, '') AS arbpl,
    CASE WHEN COALESCE(activitytype, '') <> '' THEN activitytype ELSE '' END AS lstar,
    isdd,
    isdz,
    iedd,
    iedz,
    '' AS aueru,
    '' AS zbarcodeid,
    longdate_checkin AT TIME ZONE %(timezone)s AS source_min_start,
    longdate_checkout AT TIME ZONE %(timezone)s AS source_max_end
  FROM rows
)
INSERT INTO sap_timesheet_staging (
  source_system, source_key, source_ref_id,
  werks, pernr, rueck, aufnr, vornr, flgat, plnfl, vornr_b, vornr_r,
  zconf_type, arbpl, lstar, isdd, isdz, iedd, iedz, aueru, zbarcodeid,
  source_min_start, source_max_end
)
SELECT
  source_system, source_key, source_ref_id,
  werks, pernr, rueck, aufnr, vornr, flgat, plnfl, vornr_b, vornr_r,
  zconf_type, arbpl, lstar, isdd, isdz, iedd, iedz, aueru, zbarcodeid,
  source_min_start, source_max_end
FROM payload_columns
ON CONFLICT (source_system, source_key) DO NOTHING
RETURNING id;
```

## Machine Hours Mapping

Reference:

- `API/paryload-prod-mchhours.json`
- `mch_transaction`
- `mch_statustypes`
- `react-timesheet/src/pages/MACHINE_H/MachineHoursValidationPage.jsx`
- `API/controllers/machineHoursValidationController.js`

Bundling decision:

- Pakai compact hourly duration.
- Split event yang melewati batas jam sebelum agregasi.
- `synthetic_start = bucket_start`
- `synthetic_end = bucket_start + total_seconds`
- Jangan pakai `MIN(startdatetime)` sampai `MAX(enddatetime)` sebagai payload duration, karena bisa membuat durasi palsu.

Machine payload rules:

| Payload | Source |
|---|---|
| `PERNR` | `mch_transaction.sn_employee` |
| `RUECK` | `confirmation_number`, pad left 10 untuk `M1/M2` |
| `AUFNR` | `order_no`, pad left 12 |
| `VORNR` | `operation_no`, pad left 4 |
| `FLGAT` | `sequence_category` |
| `PLNFL` | `sequence_number` |
| `VORNR_B` | `branch_operation_no` |
| `VORNR_R` | `return_operation_no` |
| `ARBPL` | `machineid` |
| `WERKS` | `.env PLANT_SSB` |
| `AUERU` | blank |

`PERNR` override:

```text
Join usernfc.snssb to mch_transaction.sn_employee.
If usernfc.employee_category contains 'Outsource':
  PERNR = '11009413'
Else:
  PERNR = original sn_employee
```

Activity mapping:

```text
status_activitytype in ('M1', 'M2')
  ZCONF_TYPE = status_activitytype
  LSTAR = ''

status_activitytype selain M1/M2
  ZCONF_TYPE = ''
  LSTAR = status_activitytype
```

`ZBARCODEID`:

```text
if ZCONF_TYPE = 'M2':
  ZBARCODEID = status_description
else:
  ZBARCODEID = ''
```

Current recommended machine filter:

- `startdatetime IS NOT NULL`
- `enddatetime IS NOT NULL`
- `enddatetime > startdatetime`
- `confirmation_number/order_no/operation_no` not blank
- do not process current incomplete hour

Row dengan `enddatetime IS NULL` artinya activity masih ongoing, jadi wajib skip. Row tersebut baru boleh masuk bucket setelah `enddatetime` terisi.

### Machine Hours Split And Bundle Query

```sql
WITH source_rows AS (
  SELECT
    proddataid,
    startdatetime,
    enddatetime,
    sn_employee,
    confirmation_number,
    order_no,
    operation_no,
    sequence_category,
    sequence_number,
    branch_operation_no,
    return_operation_no,
    status_activitytype,
    machineid,
    status_description
  FROM mch_transaction
  WHERE startdatetime IS NOT NULL
    AND enddatetime IS NOT NULL
    AND enddatetime > startdatetime
    AND confirmation_number IS NOT NULL
    AND confirmation_number <> ''
    AND order_no IS NOT NULL
    AND order_no <> ''
    AND operation_no IS NOT NULL
    AND operation_no <> ''
    AND startdatetime >= %(from_ts)s
    AND startdatetime < %(to_ts)s
),
split_rows AS (
  SELECT
    s.*,
    h.hour_bucket,
    GREATEST(s.startdatetime, h.hour_bucket) AS segment_start,
    LEAST(s.enddatetime, h.hour_bucket + interval '1 hour') AS segment_end
  FROM source_rows s
  CROSS JOIN LATERAL generate_series(
    date_trunc('hour', s.startdatetime),
    date_trunc('hour', s.enddatetime - interval '1 microsecond'),
    interval '1 hour'
  ) AS h(hour_bucket)
),
segments AS (
  SELECT
    *,
    EXTRACT(EPOCH FROM (segment_end - segment_start))::bigint AS segment_seconds
  FROM split_rows
  WHERE segment_end > segment_start
),
bundled AS (
  SELECT
    hour_bucket AS bucket_start,
    COALESCE(sn_employee, '') AS pernr,
    COALESCE(confirmation_number, '') AS rueck_raw,
    COALESCE(order_no, '') AS aufnr_raw,
    COALESCE(operation_no, '') AS vornr_raw,
    COALESCE(sequence_category, '') AS flgat,
    COALESCE(sequence_number, '') AS plnfl,
    COALESCE(branch_operation_no, '') AS vornr_b,
    COALESCE(return_operation_no, '') AS vornr_r,
    CASE
      WHEN status_activitytype IN ('M1', 'M2') THEN status_activitytype
      ELSE ''
    END AS zconf_type,
    COALESCE(machineid, '') AS arbpl,
    CASE
      WHEN status_activitytype IN ('M1', 'M2') THEN ''
      ELSE COALESCE(status_activitytype, '')
    END AS lstar,
    CASE
      WHEN status_activitytype = 'M2' THEN COALESCE(status_description, '')
      ELSE ''
    END AS zbarcodeid,
    COUNT(*)::integer AS source_row_count,
    MIN(segment_start) AS source_min_start,
    MAX(segment_end) AS source_max_end,
    SUM(segment_seconds)::bigint AS total_seconds
  FROM segments
  GROUP BY
    hour_bucket,
    COALESCE(sn_employee, ''),
    COALESCE(confirmation_number, ''),
    COALESCE(order_no, ''),
    COALESCE(operation_no, ''),
    COALESCE(sequence_category, ''),
    COALESCE(sequence_number, ''),
    COALESCE(branch_operation_no, ''),
    COALESCE(return_operation_no, ''),
    CASE
      WHEN status_activitytype IN ('M1', 'M2') THEN status_activitytype
      ELSE ''
    END,
    COALESCE(machineid, ''),
    CASE
      WHEN status_activitytype IN ('M1', 'M2') THEN ''
      ELSE COALESCE(status_activitytype, '')
    END,
    CASE
      WHEN status_activitytype = 'M2' THEN COALESCE(status_description, '')
      ELSE ''
    END
),
payload_columns AS (
  SELECT
    'MCH_HOURS' AS source_system,
    md5(concat_ws('|',
      %(werks)s,
      bucket_start::text,
      pernr,
      rueck_raw,
      aufnr_raw,
      vornr_raw,
      flgat,
      plnfl,
      vornr_b,
      vornr_r,
      zconf_type,
      arbpl,
      lstar,
      zbarcodeid
    )) AS source_key,
    NULL::text AS source_ref_id,
    %(werks)s AS werks,
    pernr,
    CASE WHEN zconf_type IN ('M1', 'M2') THEN LPAD(rueck_raw, 10, '0') ELSE '' END AS rueck,
    LPAD(aufnr_raw, 12, '0') AS aufnr,
    LPAD(vornr_raw, 4, '0') AS vornr,
    flgat,
    plnfl,
    vornr_b,
    vornr_r,
    zconf_type,
    arbpl,
    lstar,
    TO_CHAR(bucket_start, 'YYYYMMDD') AS isdd,
    TO_CHAR(bucket_start, 'HH24MISS') AS isdz,
    TO_CHAR(bucket_start + (total_seconds || ' seconds')::interval, 'YYYYMMDD') AS iedd,
    TO_CHAR(bucket_start + (total_seconds || ' seconds')::interval, 'HH24MISS') AS iedz,
    '' AS aueru,
    zbarcodeid,
    bucket_start,
    bucket_start AS synthetic_start,
    bucket_start + (total_seconds || ' seconds')::interval AS synthetic_end,
    total_seconds,
    source_row_count,
    source_min_start,
    source_max_end
  FROM bundled
  WHERE total_seconds > 0
)
INSERT INTO sap_timesheet_staging (
  source_system, source_key, source_ref_id,
  werks, pernr, rueck, aufnr, vornr, flgat, plnfl, vornr_b, vornr_r,
  zconf_type, arbpl, lstar, isdd, isdz, iedd, iedz, aueru, zbarcodeid,
  bucket_start, synthetic_start, synthetic_end, total_seconds,
  source_row_count, source_min_start, source_max_end
)
SELECT
  source_system, source_key, source_ref_id,
  werks, pernr, rueck, aufnr, vornr, flgat, plnfl, vornr_b, vornr_r,
  zconf_type, arbpl, lstar, isdd, isdz, iedd, iedz, aueru, zbarcodeid,
  bucket_start, synthetic_start, synthetic_end, total_seconds,
  source_row_count, source_min_start, source_max_end
FROM payload_columns
ON CONFLICT (source_system, source_key) DO NOTHING
RETURNING id;
```

## Posting Worker

Posting worker reads only staging:

```sql
SELECT *
FROM sap_timesheet_staging
WHERE status IN ('PENDING', 'FAILED')
ORDER BY id
LIMIT %(limit)s
FOR UPDATE SKIP LOCKED;
```

Flow:

1. Begin transaction.
2. Select rows `FOR UPDATE SKIP LOCKED`.
3. Mark rows as `POSTING`.
4. Commit.
5. POST `payload` to SAP one by one.
6. On SAP success:
   - `status = 'POSTED'`
   - `posted_at = now()`
   - save `sap_response` / `sap_response_text`
7. On SAP reject/error:
   - `status = 'FAILED'`
   - save `sap_error`
   - save response if any
8. If `source_system = 'TIMESHEET'` and SAP rejects:
   - update `timesheet_transaction.state_flag = 3`
   - clear `validation_date`
9. Keep log compatibility by inserting to `log_timesheet_sap` after every SAP attempt, using fields from staging payload.

## Script / Endpoint Plan

Suggested scripts:

```text
pythonscript/stage_timesheet_transaction.py
pythonscript/stage_machinehours.py
pythonscript/post_sap_staging.py
```

Script dipisah:

- `stage_timesheet_transaction.py`: ambil `timesheet_transaction` yang sudah checkout dari DB lokal plant, lalu insert ke AWS staging PostgreSQL. Default command polos memakai cursor `longdate_checkout`, jadi bisa catch up kalau server lokal sempat mati.
- `stage_machinehours.py`: ambil `mch_transaction` dari DB lokal plant, split dan bundle per jam, lalu insert ke AWS staging PostgreSQL. Default command polos memakai cursor sampai previous completed hour.
- `post_sap_staging.py`: ambil payload dari AWS staging PostgreSQL, lalu kirim ke SAP memakai `SAP_INBOUND_URL`, `SAP_INBOUND_USERNAME`, dan `SAP_INBOUND_PASSWORD`.

Contoh scheduler lokal per plant:

```powershell
python pythonscript\stage_timesheet_transaction.py
python pythonscript\stage_machinehours.py
```

Contoh posting SAP terpisah:

```powershell

  source_system text NOT NULL,
  plant text NOT NULL,
  last_processed_at timestamp without time zone NOT NULL,
  updated_at timestamptz NOT NULL DEFAULT now(),
  PRIMARY KEY (source_system, plant)
);
```

Cursor behavior:

- `TIMESHEET` cursor maju berdasarkan `longdate_checkout`.
- `MCH_HOURS` cursor maju berdasarkan batas akhir window machine-hour yang sudah diproses.
- Jika server lokal mati 2 jam, cursor tidak maju; saat server hidup, script catch up dari posisi terakhir.
- Query tetap memakai overlap kecil dari `SAP_STAGE_CURSOR_OVERLAP_MINUTES` supaya late update masih masuk kandidat.
- Duplicate tetap aman karena staging punya `UNIQUE (source_system, source_key)`.
- `SAP_STAGE_SAFETY_DELAY_MINUTES` membuat data paling baru belum langsung diproses, memberi waktu commit/update selesai.
- `stage_timesheet_transaction.py` membatasi source rows per run dengan `--limit` default `5000`, supaya first-run backlog tidak terasa freeze.
- `stage_machinehours.py` membatasi catch-up window per run dengan `--max-hours` default `6`.

Suggested backend migration:

- Change `POST /timesheet/post-to-sap`:
  - current: build payload and directly post
  - target: insert `TIMESHEET` rows into `sap_timesheet_staging`, then either trigger poster or return staged rows
- Machine hours validation page can also stage selected/bundled records instead of generating direct payload.

## Operational Rules

- Do not post current machine-hour bucket; process only completed hours.
- Do not stage rows with invalid or empty start/end.
- Skip `timesheet_transaction.longdate_checkout IS NULL` because that means the timesheet activity is still ongoing.
- Skip `mch_transaction.enddatetime IS NULL` because that means the machine activity is still ongoing.
- Ongoing rows are picked up in a later run after the end time is populated.
- Do not duplicate staging rows; rely on `UNIQUE (source_system, source_key)`.
- Do not regenerate `ZTIMESHEETID` during retry.
- Retry uses the same staging row and same payload.
- If a source row was staged with wrong mapping, mark old staging row `SKIPPED` and create a controlled rebuild process.

## Open Decisions

- Unproductive `ZBARCODEID`: current backend sends blank, but `payload-unproductive.json` shows a value.
- `PERNR` padding for machine hours: current machine-hour controller does not pad; timesheet controller pads to 8.
- Whether non-`M1/M2` machine-hour activities should be staged if order/confirmation exists.
